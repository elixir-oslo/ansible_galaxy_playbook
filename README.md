# Galaxy Ansible Playbook

Compact Ansible toolkit to deploy Galaxy (`release_26.0`) with PostgreSQL 16, Gravity/Gunicorn, and Nginx on Debian/Ubuntu targets.

Main entrypoint: `deploy.sh`

## What This Deploys

- Galaxy server from `https://github.com/galaxyproject/galaxy.git` at `release_26.0`
- PostgreSQL 16 + Galaxy DB/user provisioning
- Gravity + Gunicorn on `127.0.0.1:8080`
- Nginx on port `80` proxying to Galaxy
- Micromamba/Conda tool dependency stack
- Node.js 22 + Corepack for client build tooling

### Pinned role versions (`requirements.yml`)

| Role | Version |
|---|---|
| `galaxyproject.galaxy` | `0.12.1` |
| `galaxyproject.nginx` | `1.0.2` |

| `usegalaxy_eu.certbot` | `0.1.13` |

## Single Source of Truth

Edit only `group_vars/galaxyservers.yml` before deployment.

- **Top section** (`galaxy:`, `database:`, `admin:`) is parsed by `deploy.sh` to generate `hosts`
- **Lower section** (`galaxy_*`, `postgresql_*`, `miniconda_*`, etc.) is consumed by Ansible roles/tasks

`hosts` is auto-generated by `deploy.sh`. Do not edit it manually when using the script.

### Required values

```yaml
galaxy:
  host_ip: "1.2.3.4"
  ssh_user: "ubuntu"

database:
  password: "CHANGE_ME_STRONG_PASSWORD"

admin:
  email: "admin@example.com"
```

## Quick Start (Recommended)

```bash
chmod +x deploy.sh
./deploy.sh
```

Use menu option `1` (`full_remote`) for end-to-end remote deployment.

## Manual Playbook Usage (Without `deploy.sh`)

If you run `ansible-playbook` manually, create your inventory from the sample:

```bash
cp hosts.sample hosts
```

Then edit `hosts` and replace these required values in the remote block:

- `YOUR_SERVER_IP_OR_DOMAIN`
- `YOUR_SSH_USER`

After that, run:

```bash
source venv/bin/activate
ansible-playbook -i hosts galaxy.yml --flush-cache
```

When using `deploy.sh`, do not manually maintain `hosts` because it is regenerated automatically.

## Deployment Menu (`deploy.sh`)

| Option | Action |
|---|---|
| `1` | Full remote flow (`prepare -> roles -> syntax-check -> ping -> deploy -> validate`) |
| `2` | Prepare control node (`venv`, install `ansible` + `yq`) |
| `3` | Install roles (`ansible-galaxy install -r requirements.yml --force`) |
| `4` | Test SSH (`ansible ... -m ping`) |
| `5` | Deploy remote (`ansible-playbook galaxy.yml --flush-cache`) |
| `6` | Validate remote API (`curl -sf http://127.0.0.1/api/version`) |
| `7` | Deploy local (Linux only) |
| `8` | Clean local (`venv/`, `.tmp/`) |
| `9` | Clean remote environment (destructive) |
| `10` | Publish generated role branch/tag |
| `11` | Exit |

## Architecture (`galaxy.yml`)

Three-play sequence:

1. `galaxyservers`: install PostgreSQL 16 (`galaxyproject.postgresql`)
2. `dbservers`: create DB/user as `postgres` (`galaxyproject.postgresql_objects`)
3. `galaxyservers`: deploy Galaxy + Miniconda + manual Nginx config

### Important behavior from the playbook

- Node DNS workaround is applied globally:
  - `/etc/environment`: `NODE_OPTIONS=--dns-result-order=ipv4first`
  - `/etc/profile`: `export NODE_OPTIONS=--dns-result-order=ipv4first`
- `galaxyproject.galaxy` runs with client build disabled during role execution
- Client build is executed later in `post_tasks` (controlled by `build_galaxy_client_after_api`, default `true`)
- Nginx is configured manually in `post_tasks` (`/etc/nginx/sites-available/galaxy`)
- Health checks include waiting for port `8080` and validating `/api/version`

## Control Node and Target Requirements

- Control node: macOS or Linux
- Target node: Linux (Debian/Ubuntu with `apt` + `systemd`)
- Required on control node before running: `bash`, `python3`, `yq`

Example install for macOS:

```bash
brew install yq
```

## Validation and Helper Scripts

### Syntax check only

```bash
source venv/bin/activate
ansible-playbook -i hosts galaxy.yml --syntax-check
```

### Quick pre-deploy checks from control node

```bash
bash devops-scripts/test_playbooks.sh
```

### Post-deploy server validation (run on target host)

```bash
bash devops-scripts/validate_galaxy.sh
```

`validate_galaxy.sh` checks:

- `galaxyctl` service status
- Listening ports `8080` and `80`
- Internal and external API responses
- PostgreSQL usage (no SQLite fallback)
- Restart resilience for Galaxy and Nginx

## Useful Runtime Checks

```bash
curl http://127.0.0.1:8080/api/version
curl http://<server>/api/version
sudo -u galaxy /srv/galaxy/venv/bin/galaxyctl -c /srv/galaxy/config/galaxy.yml status
```

| Config | `/srv/galaxy/config/galaxy.yml` |
| Virtualenv | `/srv/galaxy/venv` |

## Role Generation and Publishing

The repository includes tooling to sync `galaxy.yml` into a reusable role and publish it.

- Sync playbook into role files: `devops-scripts/sync_galaxy_playbook_to_role.py`
- Publish role branch/tag: `devops-scripts/publish_galaxy_role_branch.sh`
- Interactive wrapper: menu option `10` in `deploy.sh`

Role usage docs: `docs/using-galaxy-deployment-role.md`
