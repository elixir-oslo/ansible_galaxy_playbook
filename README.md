# Galaxy Ansible Playbook

An Ansible deployment toolkit for Galaxy with PostgreSQL, Gravity, and Nginx.

The main entrypoint is `deploy.sh`.

---

## What gets deployed

From `galaxy.yml`, `requirements.yml`, and `group_vars/galaxyservers.yml`:

- Galaxy `release_25.0` from `https://github.com/galaxyproject/galaxy.git`
- PostgreSQL 16 and Galaxy DB schema
- Galaxy services via Gravity (gunicorn, port `8080`)
- Nginx reverse proxy (port `80`)
- Micromamba-based tool dependency stack (conda-forge, Python 3.11)

Installed roles (`requirements.yml`):

| Role | Version |
|------|---------|
| `galaxyproject.galaxy` | `0.12.1` |
| `galaxyproject.nginx` | `1.0.2` |
| `galaxyproject.postgresql` | `1.1.2` |
| `galaxyproject.postgresql_objects` | `1.2.0` |
| `galaxyproject.miniconda` | `0.3.3` |
| `usegalaxy_eu.certbot` | `0.1.13` |

## Prerequisites

### Control node (where `deploy.sh` runs)

| Tool | Notes |
|------|-------|
| `bash` | Required |
| `python3` | Required |
| `yq` | Required — used to parse `group_vars/galaxyservers.yml` |

`deploy.sh` creates a `venv/` and installs `ansible` and `yq` inside it automatically via **Prepare control node**.

### Platform support

- **macOS**: supported as control node (`brew install yq`)
- **Linux**: supported as control node and as local Galaxy deployment target
- **Remote target**: must be Linux (Debian/Ubuntu) with `systemd` and `apt`

## Configuration

All deployment parameters live in a **single file**: `group_vars/galaxyservers.yml`.

Edit the values at the top of the file before running:

```yaml
galaxy:
  host_ip: "Real.Hosting.IP.Address"   # Target VM IP or hostname
  ssh_user: "ubuntu"                    # SSH user on the target

paths:
  galaxy_root: "/srv/galaxy"

database:
  password: "CHANGE_ME_STRONG_PASSWORD"

admin:
  email: "admin@example.com"
```

`deploy.sh` reads this file with `yq` and auto-generates the `hosts` inventory file.

## Menu actions

| # | Action | Function | Description |
|---|--------|----------|-------------|
| 1 | Full automated remote deployment | `full_remote` | Runs end-to-end remote flow: prepare venv, install roles, syntax-check, SSH test, deploy, and API validation. |
| 2 | Prepare control node (venv) | `prepare_control_node` | Creates a fresh Python virtual environment and installs local execution dependencies (`ansible`, `yq`). |
| 3 | Install Ansible role dependencies | `install_roles` | Installs roles from `requirements.yml` using `ansible-galaxy install --force`. |
| 4 | Test SSH connectivity | `test_connection` | Loads config, generates inventory, and runs `ansible ... -m ping` against `galaxyservers`. |
| 5 | Deploy Galaxy (remote) | `deploy_remote` | Executes `galaxy.yml` on the remote target host(s) using the generated inventory. |
| 6 | Validate remote Galaxy API | `validate_remote` | Verifies Galaxy API responds on the target via `curl -sf http://127.0.0.1/api/version`. |
| 7 | Deploy locally (Linux only) | `deploy_local` | Switches to local inventory mode and runs `galaxy.yml` on `localhost` (Linux only). |
| 8 | Clean local venv/tmp | `clean_local` | Removes local `venv/` and `.tmp/` after confirmation. |
| 9 | Wipe remote Galaxy environment | `clean_remote` | Stops services and removes Galaxy/PostgreSQL/Nginx data and configs on the remote host. |
| 10 | Exit | — | Exits the interactive menu. |

## Recommended flow

### Remote deployment

```
2 → Prepare control node
3 → Install roles
4 → Test SSH
5 → Deploy Galaxy
6 → Validate
```

Or use **option 1** (`full_remote`) to run the full sequence automatically.

### Local deployment (Linux only)

Use **option 7** after running **option 2** (prepare control node).

## `galaxy.yml` behavior

Three plays run in sequence:

1. **Play 1** — Install PostgreSQL 16 on `galaxyservers`
2. **Play 2** — Create Galaxy DB user/database on `dbservers`
3. **Play 3** — Deploy Galaxy + Miniconda + Nginx on `galaxyservers`

**Play 3 pre-tasks:**
- Installs/upgrades Node.js 20 (removes older versions if present)
- Stops any running Galaxy instance
- Installs system dependencies (`build-essential`, `git`, `python3-venv`, `nginx`, etc.)

**Play 3 post-tasks:**
- Initializes Galaxy DB schema (idempotent, first run only)
- Starts Galaxy and Nginx services
- **Bootstrap block** (runs once, guarded by `/var/lib/galaxy/bootstrap.done`):
  - Creates nginx config with proxy to gunicorn socket
  - Resets Gravity state
  - Verifies API via nginx (`http://localhost/api/version`)
  - Marks bootstrap complete
- Installs final nginx config with static asset serving and `10G` upload limit
- Fixes static file ownership and permissions (`/srv/galaxy/server/static`)
- Final health checks: gunicorn binary, port `8080`, and API response

## Common checks

```bash
# Galaxy internal API (on the server)

# Galaxy API via nginx (from outside)
curl http://<server>/api/version

```

## Troubleshooting

| Symptom | Action |
|---------|--------|
| `yq` not found | Install via `brew install yq` (macOS) or `sudo apt install yq` (Linux) |
| `group_vars/galaxyservers.yml` missing `galaxy.host_ip` | Edit the file and set the correct IP |
| SSH test fails | Verify host/user/key and re-run option 4 |
| Deployment fails | Check logs on the target: `/srv/galaxy/mutable/gravity/log/gunicorn.log` |
| Static assets missing | Re-run option 5 — play 3 post-tasks fix permissions automatically |
